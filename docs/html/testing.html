Prekondisi: Frontend berjalan di port dev server.		 UI menampilkan tata letak 3 kartu terpisah (Credentials, Persona/Knowledge, Responses) secara rapi dan estetis. Puppeteer memuat rute /chatbot-ai, sukses memverifikasi keberadaan visual 3 kartu terpisah, dan mengambil bukti screenshot. Passed
TC-SYS-01 Skenario: Pengujian otomatis menyeluruh (full system).

Prekondisi: Direktori sesi berada di backend.		 Direktori kredensial terisolasi dari webroot frontend. Pengujian terpisah diperlukan untuk ACL dan enkripsi at-rest produksi. Skrip uji memeriksa lokasi direktori backend saja; hasil ini bukan bukti enkripsi filesystem. Passed
TC-SEC-02 Skenario: Sanitasi SQL Injection di REST API.
Prekondisi: Mengirim payload isian SQL berbahaya ke API.		 Backend menangani escape character SQL dengan aman (Prepared Statements) dan tidak memicu database crash. Mengirim parameter bermasalah (session' OR '1'='1) sukses ditangani database secara aman tanpa crash atau kebocoran data. Passed
TC-SEC-03 Skenario: Masking API Key Sensitif pada UI.
Prekondisi: Halaman /chatbot-ai dimuat.		 Elemen input API Key menggunakan tipe masked (password) secara default agar tidak terbaca visual. Atribut input API Key di UI terverifikasi memiliki type="password" yang menyembunyikan string key demi keamanan. Passed
TC-SEC-04 Skenario: Middleware keamanan backend dan enkripsi secret AI.
Prekondisi: QA unit security dijalankan.		 CORS menolak origin asing, key salah menghasilkan 401, rate limit menghasilkan 429, respons tidak membocorkan provider key, dan ciphertext AES-256-GCM dapat dipulihkan. Skrip QA menguji middleware dan helper secret secara lokal tanpa mengekspos key produksi. Passed
TC-SEC-05 Skenario: Admin dashboard authentication.
Prekondisi: WA_BOT_ADMIN_PASSWORD aktif.		 API menolak request tanpa cookie admin, login menghasilkan cookie HttpOnly, dan cookie valid dapat mengakses endpoint terlindungi. Smoke test auth dan unit QA middleware admin berhasil memvalidasi alur login/cookie. Passed
TC-OPT-01 Skenario: Suppression list opt-out.
Prekondisi: QA helper opt-out dijalankan.		 Keyword opt-out dikenali, nomor dinormalisasi, dan suppression list dapat menyimpan serta menghapus nomor. Skrip QA berhasil melakukan round-trip data suppression tanpa meninggalkan nomor uji. Passed
TC-MEDIA-01 Skenario: Pengunggahan lampiran media admin.
Prekondisi: Gambar <= 5 MB dan video <= 10 MB diunggah dari UI.		 File media terverifikasi jenis ekstensi dan MIME tipenya, diberi nama acak, disimpan di folder uploads, dan terkirim dengan sukses. Sanitasi nama, pencegahan spoofing ekstensi, dan pengiriman lampiran media terverifikasi lulus secara penuh di backend & UI. Passed
TC-FLOW-03 Skenario: Impor Chatbot Flow ukuran besar.
Prekondisi: Mengimpor berkas JSON flow ukuran 60 MB.		 Proses parsing JSON flow asinkron berhasil dimuat secara non-blocking di UI dengan indikator persentase progress. Import data besar sukses terverifikasi di staging VPS, UI menunjukkan persentase progress, dan metrics tersimpan akurat. Passed
TC-RECON-02 Skenario: Pemulihan berkala sesi terputus (Auto-Repair).
Prekondisi: Status sesi berubah DISCONNECTED di staging.		 Skrip auto-repair periodik mendeteksi kegagalan, menjalankan perbaikan, membatasi laju perbaikan (3x/24j), dan mengirim notifikasi Telegram. Sesi sukses diperbaiki dan dihubungkan kembali tanpa loop tak terbatas. Notifikasi Telegram diterima dengan benar saat limit tercapai. Passed
TC-FLOW-04 Skenario: Deteksi & Visualisasi Galat API Chatbot AI.
Prekondisi: Token AI habis atau provider error saat memproses pesan.		 Galat API tertulis persisten di database, dan dashboard memunculkan Alert Box merah glassmorphic self-healing secara real-time. Galat terekam di kolom `last_error`, UI dashboard merender Alert Box dengan badge klasifikasi galat secara akurat. Passed

Aspek PengujianMetode & PendekatanPeralatan / Tools QA
