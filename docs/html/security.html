Kontrol Keamanan Aktif #

Daftar kontrol keamanan utama yang telah diimplementasikan dalam kode backend dan frontend WA-Bot Pro.

Admin Auth
Login cookie HttpOnly via WA_BOT_ADMIN_PASSWORD. X-API-Key untuk server-to-server.
Encryption
AES-256-GCM wajib untuk session/provider secrets; tidak ada fallback statis. Backup terenkripsi memakai WA_BOT_BACKUP_ENCRYPTION_KEY.
Rate Limiting
In-memory per-IP limiter. Multi-instance: gunakan Caddy/Nginx rate-limit plugin atau Redis.
CORS
Allowlist via WA_BOT_ALLOWED_ORIGINS. Staging menggunakan domain HTTPS spesifik.
CSP & Headers
CSP tuned untuk Google Fonts dan WebSocket staging/prod. Frame denial, referrer policy, permissions policy, dan HSTS opsional.
ACL Filesystem
Env file 640, sessions/database restricted. Template dedicated user tersedia di security_acl.commands.txt.

Backend Hardening #

Detail pengerasan keamanan pada layer backend API dan integrasinya:

  • JWT Dashboard: WA_BOT_ADMIN_SESSION_SECRET wajib minimal 32 karakter dan refresh token dikonsumsi atomik untuk menolak concurrent replay.
  • Akses X-API-Key Opsional: Dikendalikan oleh WA_BOT_API_KEY untuk pemanggil server-to-server yang tepercaya.
  • Rate Limiting API In-Memory: Dikendalikan oleh WA_BOT_RATE_LIMIT_MAX and WA_BOT_RATE_LIMIT_WINDOW_MS per IP.
  • CORS Origins Dibatasi: Dikendalikan oleh WA_BOT_ALLOWED_ORIGINS.
  • Menonaktifkan Header X-Powered-By: Header default Express dinonaktifkan untuk menyembunyikan identitas software.
  • Header Keamanan Bawaan: Konfigurasi CSP, frame denial (X-Frame-Options), MIME sniffing protection (X-Content-Type-Options), referrer policy, permissions policy, dan HSTS opsional.
  • Kebijakan Ukuran Permintaan (Request-Size Policy): Dikendalikan oleh WA_BOT_JSON_BODY_LIMIT (default 2mb) dan WA_BOT_IMPORT_BODY_LIMIT (default 60mb) untuk impor chatbot flow/kontak yang besar.
  • Penyimpanan Upload Media: Limit gambar <= 5 MB dan video <= 10 MB disimpan di bawah backend/uploads/ atau WA_BOT_MEDIA_UPLOAD_DIR.
  • Masking Kunci API Chatbot AI: Menyamarkan respons kunci dengan metadata has_api_key.
  • Enkripsi Secret Wajib: WA_BOT_SECRET_ENCRYPTION_KEY minimal 32 karakter melindungi sesi dan provider key; penyimpanan gagal tertutup jika tidak tersedia.
  • Boundary Media/Session: Media dibatasi ke managed upload root dan session path dibatasi ke ID aman.
  • Anti-SSRF AI: Provider hanya public HTTPS dengan DNS/private-range validation dan redirect rejection.
  • Tenant & Log Hardening: Synced contacts/templates diperiksa pemiliknya dan body/secret tidak dicatat mentah.
  • Upgrade sqlite3@6.x: Mengatasi kerentanan audit dependensi dengan keselarasan versi terbaru.
  • Rotasi Placeholder Kredensial Staging: Kunci dan token placeholder dirotasi secara aman, diuji dengan HTTPS smoke test.
  • Masking Kredensial Proxy & IPLocate: Mencegah kebocoran plaintext kredensial dalam respons setelan dan detail sesi.
  • Evaluasi Rate-Limiting Multi-Proses: Menggunakan limiter in-memory untuk VPS staging single-instance, dan menyarankan Caddy/Nginx plugin atau Redis cache untuk lingkungan produksi multi-instance.
  • ACL Filesystem Staging VPS: Izin file env diatur ke 640, direktori database dan sesi hanya dapat diakses oleh user/group ubuntu.

Minimum Production Checklist #

Bind backend ke private interface atau lindungi dengan reverse proxy.
Terminate TLS di reverse proxy. Set WA_BOT_COOKIE_SECURE=true setelah HTTPS aktif.
Konfigurasi WA_BOT_ADMIN_PASSWORD dan WA_BOT_ADMIN_SESSION_SECRET, atau authenticated gateway.
Konfigurasi rate limiting, request size limits, dan restricted CORS origins.
Jalankan npm run security:audit dan catat hasilnya di docs/SECURITY_AUDIT.md.
Enkripsi disk dan batasi akses ke backend/sessions/ dan backend/database.sqlite.
Konfigurasi WA_BOT_SECRET_ENCRYPTION_KEY; pindahkan API keys ke managed secrets.
Backup SQLite database dan uji prosedur restore.
Catat evidence uji keamanan untuk setiap release candidate.

Messaging & Privacy Rules #

Kebijakan operasional yang harus ditaati untuk setiap penggunaan sistem messaging.

Kirim pesan hanya kepada penerima yang telah memberikan consent.
Sediakan dan hormati proses opt-out. Kata kunci otomatis: STOP, UNSUBSCRIBE, BERHENTI.
Jangan gunakan warmer atau bulk messaging untuk menghindari kontrol platform.
Minimalkan data kontak yang disimpan dan tetapkan periode retensi log.
Detail lengkap kebijakan consent, opt-out, retensi, dan media upload lifecycle tersedia di docs/PRIVACY.md.

Incident Response #

Prosedur yang harus diikuti jika sesi atau API key mungkin telah dikompromikan.

1
Hentikan proses backend.
2
Putuskan perangkat WhatsApp yang terpengaruh dari telepon.
3
Rotasi provider keys dan proxy credentials.
4
Arsipkan log yang diperlukan untuk investigasi tanpa mengekspos secret.
5
Hapus file auth lokal yang dikompromikan hanya setelah mengonfirmasi direktori sesi yang tepat.
6
Pulihkan layanan dan dokumentasikan timeline insiden.
