Pengantar, Autentikasi & Rate Limiting #

RESTful API WA-Bot Pro dikembangkan dengan arsitektur REST tradisional menggunakan format pertukaran data JSON. Base URL resmi untuk seluruh pemanggilan API lokal adalah:
http://localhost:3001/api

Skema Autentikasi:

Status implementasi: middleware autentikasi tersedia dan aktif ketika environment variable WA_BOT_API_KEY diisi. Untuk deployment browser publik, gunakan authenticated gateway atau server-side session layer agar secret backend tidak ditanam di JavaScript frontend:
X-API-Key: <YOUR_API_KEY>

Dashboard browser memakai JWT access/refresh cookie HttpOnly. Role admin dapat mengelola user, melihat Monitoring, audit log, dan paket langganan; role user hanya mengakses resource miliknya sendiri. OpenAPI utama berada di docs/openapi.yaml dan saat ini parity dengan 113 handler Express.

Kebijakan Jeda Kecepatan (Rate Limiting):

Status implementasi: rate limiting in-memory diterapkan pada seluruh rute /api/*. Konfigurasi default:
- Endpoint Umum: Maksimal 120 permintaan per menit per alamat IP.
- Konfigurasi: WA_BOT_RATE_LIMIT_MAX dan WA_BOT_RATE_LIMIT_WINDOW_MS.
Sistem mengembalikan status HTTP 429 Too Many Requests jika batas terlampaui.

Standardisasi Respons Error #

Sistem WA-Bot Pro menggunakan struktur payload JSON yang seragam untuk seluruh kesalahan HTTP. Struktur ini memuat kode status, pesan penjelas, serta rincian kesalahan jika relevan.

Tabel 3.6.1 -- Kode Status HTTP Error yang Didukung Sistem
KodeNama StatusPemicu Utama
400Bad RequestParameter masukan tidak valid, tipe data salah, atau JSON rusak.
401UnauthorizedHeader API key hilang atau tidak cocok ketika WA_BOT_API_KEY diaktifkan.
404Not FoundTarget resource (sesi, kampanye, templat, dsb) tidak ditemukan di DB.
429Too Many RequestsMelampaui kuota pemanggilan per menit yang dikonfigurasi.
500Internal Server ErrorKegagalan sistem internal, crash socket, atau korupsi database SQLite3.
Contoh Payload Error JSON (400 Bad Request)
{
  "status": "error",
  "error_code": "VALIDATION_ERROR",
  "message": "Nomor telepon tujuan tidak valid.",
  "details": {
    "targets": "Parameter targets harus berupa array dengan kode negara internasional valid (ex: 628xxx)."
  }
}
Contoh Payload Error JSON (404 Not Found)
{
  "status": "error",
  "error_code": "RESOURCE_NOT_FOUND",
  "message": "Sesi WhatsApp dengan ID 'wa-marketing-1' tidak ditemukan."
}

User Management & SaaS Controls

GET POST PATCH /api/users Admin-only user lifecycle

Endpoint User Management hanya untuk admin. Admin dapat membuat user tenant, mengubah role/status, mengganti password, dan mengatur kuota WhatsApp device melalui field device_limit.

Field Entitlement
ParameterTipeKeterangan
device_limitinteger optionalRentang 0-100. Default 1. User non-admin ditolak membuat session baru ketika jumlah session miliknya sudah mencapai nilai ini.
rolestring optionaladmin memiliki akses global dan Monitoring; user hanya tenant-scoped.
is_activeboolean optionalMenonaktifkan akses user tanpa menghapus data tenant.
Request Example
{
  "username": "tenant-a",
  "password": "PasswordMinimal12!",
  "display_name": "Tenant A",
  "role": "user",
  "device_limit": 3
}

Request Body Parameters
ParameterTipeKeterangan
session_idstring requiredID sesi WhatsApp unik yang ingin dibuat.
Request Example

{

{

  "data": {
    "session_id": "wa-kantor-1",

POST /api/chatbot-flows Create New Flow

Membuat alur chatbot interaktif baru dengan skema node, pemicu kata kunci, cooldown, dan opsi penundaan.

Request Body Parameters
ParameterTipeKeterangan
flow_namestring requiredNama alur chatbot.
session_idsarray requiredArray ID sesi WhatsApp pengirim.
keywordsarray requiredDaftar kata kunci pemicu alur chatbot.
nodesarray/object requiredSkema graph JSON yang mewakili langkah-langkah percakapan.
match_typestring optionalPilihan: EXACT, CONTAINS, STARTS_WITH. Default: CONTAINS.
cooldownnumber optionalWaktu tunggu antar trigger per kontak (menit). Default: 0.
delaynumber optionalJeda simulasi mengetik sebelum membalas (detik). Default: 0.
Request Example
{

  "session_ids": ["wa-kantor-1"],

    "start": {
      "type": "text",
      "message": "Silakan pilih menu: \n1. Info Harga \n2. Hubungi Agen"

  },
  "match_type": "EXACT",
  "cooldown": 5,
  "delay": 2
}

{
  "status": "success",
  "message": "Flow chatbot berhasil disimpan.",

    "id": 2,
    "flow_name": "CS Support"
  }
}

{
  "status": "error",
  "message": "Kolom 'flow_name' dan 'nodes' wajib diisi."

Uploads, Plans & Audit
POST /api/uploads/media Upload Media

Mengunggah gambar maksimal 5 MB, video maksimal 10 MB, audio maksimal 2 MB, atau dokumen maksimal 5 MB. Upload membutuhkan subscription aktif dan metadata file disimpan di tabel uploaded_media dengan pemilik user_id.

GET /api/uploads/media/:filename Download Uploaded Media

Mengunduh media runtime melalui auth. Implementasi saat ini hanya mengizinkan pemilik file yang tercatat di uploaded_media. File lama tanpa metadata ditolak fail-closed.

DELETE /api/uploads/media/:filename Delete Uploaded Media

Menghapus file media runtime dan metadata uploaded_media. Implementasi saat ini hanya mengizinkan pemilik file menghapus media tersebut.

GET /api/plans List Subscription Plans

Endpoint admin-only untuk daftar paket SaaS. Paket mengatur max_sessions, max_campaigns_per_month, dan max_flows yang dipakai oleh middleware entitlement.

POST /api/plans Create Subscription Plan

Membuat paket langganan baru. Jika is_default aktif, paket default lama dinonaktifkan secara otomatis.

PUT /api/plans/:id Update Subscription Plan

Memperbarui batas paket. Enforcement runtime membaca nilai paket terkini, termasuk limit device dari max_sessions.

DELETE /api/plans/:id Delete Subscription Plan

Menghapus paket jika tidak sedang digunakan user. Paket yang masih direferensikan oleh user ditolak untuk menjaga konsistensi entitlement.

GET /api/audit-logs List Audit Logs

Mengambil audit trail append-only. Admin melihat seluruh event; user biasa hanya event dirinya sendiri. Filter tersedia untuk event_type, target_type, result, page, dan limit.

Internal Process API
GET /internal/health/live Internal Liveness

Endpoint liveness untuk proses internal seperti sessions, worker, campaign-worker, dan warmer-worker. Tidak membutuhkan token karena hanya mengembalikan status hidup proses.

GET /internal/health/ready Internal Readiness

Endpoint readiness internal yang mengembalikan role, uptime, status database, jumlah sesi aktif, dan status polling worker.

GET /internal/sessions List Sessions via Session Manager

Mengambil daftar sesi dari proses session manager. Wajib memakai header X-Internal-Token yang sama dengan WA_BOT_INTERNAL_TOKEN.

POST /internal/sessions/:id/init Initialize Session via Session Manager

Menginisialisasi sesi Baileys di proses session manager. Dipakai oleh API-only mode ketika WA_BOT_SESSION_MANAGER_URL dikonfigurasi.

GET /internal/sessions/:id Get Session via Session Manager

Mengambil status satu sesi langsung dari proses session manager, termasuk QR code sementara jika sesi masih menunggu pemindaian.

DELETE /internal/sessions/:id Delete Session via Session Manager

Menghapus sesi dan credential lokal melalui proses session manager. Operasi ini sensitif dan hanya boleh dipanggil dari proses internal tepercaya.

PATCH /internal/sessions/:id/proxy Update Session Proxy via Session Manager

Mengubah proxy sesi melalui proses session manager, lalu memutus socket aktif agar Baileys melakukan reconnect dengan konfigurasi terbaru.
